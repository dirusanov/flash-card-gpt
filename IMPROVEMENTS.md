## Оценка идеи

Идея здравая и ниша реальная: BYOK-расширение, которое превращает выделенный текст в готовую
карточку (перевод + транскрипция + примеры + аудио + картинка + грамматика) и кладёт её в Anki
или в своё облако. Ручной флоу «скопировал → ChatGPT → отформатировал → Anki» занимает минуты,
здесь это один клик — экономия ощутимая, за такое платят.

Слабое место идеи — **тройная модель настройки**: свой OpenAI-ключ + аккаунт Vaulto + локальный
Anki с AnkiConnect. Три независимые интеграции, каждая может отвалиться отдельно, и ни одна не
объяснена пользователю в момент установки. Конкуренты (Migaku, Language Reactor, Toucan) берут
подписку и не требуют ключа — у них барьер входа ниже.

Плюс режим General Topic, который есть в README и в коде, принудительно выключен
(`src/components/CreateCard.tsx:1711` жёстко ставит `LanguageLearning` на каждом рендере) — то есть
заявленная универсальность «карточка на любую тему» сейчас недоступна, остался только
language learning. Это сильно сужает аудиторию по сравнению с тем, что обещает README.

## Критичное (чинить до публикации)

### 1. OpenAI-ключ и JWT утекают в localStorage любого сайта

`src/services/apiKeyStorage.ts:127` (`saveApiKeys` → `writeFallback`) и
`src/services/authStorage.ts:71` (`setSession` → `writeFallback`) пишут в `window.localStorage`
**безусловно**, а не только когда `chrome.storage` недоступен.

Content script делит localStorage с origin страницы, поэтому любой скрипт на сайте — рекламный,
аналитика, XSS — читает `localStorage.getItem('anki_api_keys_v1')` и получает ключ OpenAI и
refresh-токен Vaulto. Это и деньги пользователя, и угон аккаунта.

**Сделано** (`14c182e`). `writeFallback`/`readFallback` удалены из обоих файлов — секреты живут
только в `chrome.storage.local`. Добавлен `src/services/legacyLocalStorageCleanup.ts`: на каждой
странице он забирает уже утёкшие значения в `chrome.storage.local` (только если там пусто) и
удаляет их из localStorage сайта. Если хранилище расширения недоступно, зеркало не трогается —
удалять ключ, не сумев его перенести, хуже, чем оставить до следующей загрузки страницы. Заодно
убрана запись deck id в localStorage.

Очистка работает по мере посещения сайтов: на origin, куда пользователь больше не вернётся,
зеркало останется. Это приемлемо — данные лежат в его же профиле, — но означает, что «оно само
вычистится» неверная модель.

**Осталось вручную:** ротировать ключ OpenAI и инвалидировать выданные refresh-токены. Опасность
не в том, что данные лежали, а в том, что их могли прочитать: всё время работы уязвимой версии
доступ к ним имел любой скрипт на любом сайте, где открывалась панель. Очистка этого не отменяет.

Не тронуты `settingsPersistence.ts` и `deckSelectionPersistence.ts` — они используют тот же
паттерн зеркалирования, но хранят только настройки и id колоды, без учётных данных. Это
загрязнение localStorage сайтов, а не утечка; стоит вычистить отдельно.

### 2. Расширение на 1.27 МБ монтируется на каждой странице, даже если им не пользуются

`src/pages/Content/index.js:729` вызывает `warmInitializeApp()` безусловно, при
`run_at: document_start` и `matches: <all_urls>`. React + Redux + KaTeX + OpenAI SDK поднимаются
в каждой вкладке. При 20 открытых вкладках это 20 инстансов приложения в памяти и замедление
загрузки всех сайтов.

**Сделано частично** (`f6b025d`). `warmInitializeApp()` убран, приложение монтируется лениво — по
первому сообщению, которому нужен UI. На страницах, где панель не открывали, больше нет ни
React-дерева, ни Redux-стора, ни четырёх подписчиков персистентности, ни глобального `mouseup`
из №7.

**Закрыто полностью** переездом на боковую панель (`69cf440`, `5.1.0`). React, Redux и KaTeX уехали
в панель, которая грузится по требованию. Content script на странице теперь тонкий мост:
**17 КБ вместо 1.27 МБ**. На страницах, где панель не открывали, тяжёлого кода нет вообще.

### 3. `document.body.style.marginRight = '350px'` ломает вёрстку сайтов

`src/pages/Content/index.js:242`. Фиксированные шапки не сдвигаются, sticky-элементы съезжают,
сайты со своим margin на body получают перезапись (при закрытии ставится `0`, а не исходное
значение). Это самая частая жалоба на sidebar-расширения.

**Сделано** — переезд на нативную `chrome.sidePanel` (`69cf440`, `5.1.0`). Панель теперь рисует
сам Chrome сбоку от вкладки, `body` страницы не трогается вообще: ни `marginRight`, ни shadow DOM,
ни оверлеев. Вёрстка любого сайта остаётся нетронутой.

Что пришлось перестроить по пути:

- **Плавающее окно удалено** — внутри браузерной панели перетаскиваемого окна не бывает. Вместе с
  ним ушли редьюсеры `view`/`sidebar` и настройки вида по вкладкам (см. №12).
- **Доступ к DOM страницы вынесен за messaging.** `CreateCard` читал страницу в трёх местах;
  теперь это запросы к content script через `src/services/pageContextBridge.ts`, возвращают `null`
  на недоступной вкладке (`chrome://`, ещё грузится) — карточка создаётся без контекста страницы.
- **Передача выделения переведена на storage** (`pendingSelection.ts`): background и панель —
  разные документы, общий модуль их больше не связывает, а панель после открытия ещё грузится.

Стилевая регрессия переезда (инпуты вылезали за контейнер, потому что preflight Tailwind приходил
через shadow DOM) исправлена в `9cc7121` — панель, попап и настройки теперь бандлят стили сами.

### 4. Пустая страница настроек

Манифест объявляет `options_page: "options.html"`, но `src/pages/Options/index.jsx` — 0 байт,
`build/options.bundle.js` — 0 байт. Клик «Параметры» в `chrome://extensions` даёт белый экран.
Там же лишний `devtools_page` (82 байта boilerplate), который без нужды расширяет права.

**Сделано** (`19a3b58`). Страница рендерит форму настроек под коротким интро из трёх шагов.
`devtools_page` убран из манифеста, а сами страницы Devtools, Panel и Newtab удалены — на них не
ссылался ни один ключ манифеста.

### 5. Права пугают пользователя

`host_permissions: ["https://*/*", "http://*/*"]` + `<all_urls>` в content_scripts → Chrome
покажет «Читать и изменять все ваши данные на всех сайтах». Реально расширение ходит только на
`api.openai.com`, `auth.vaultonote.com` и localhost. Широкие права режут конверсию установки и
тормозят ревью в Chrome Web Store.

**Сделано частично** (`19a3b58`). `host_permissions` сужены до реально используемых хостов:
OpenAI, его хранилище картинок, два сервиса Vaulto и localhost для AnkiConnect. Записи про
huggingface и jsdelivr относились к коду, которого больше нет. В content_scripts убран
`<all_urls>` — остались только http/https, то есть отдан доступ к `file://`.

**Осталось:** предупреждение «на всех сайтах» никуда не делось. Его вызывает не `host_permissions`,
а декларативный content script с матчем на все хосты. После переезда на панель этот скрипт стал
тонким (17 КБ) и нужен для чтения выделения и контекста страницы, но матч всё ещё на все хосты.
Чтобы убрать предупреждение, нужен `activeTab` плюс инъекция через `chrome.scripting` по действию
пользователя. Цена — пропадёт автоподстановка выделения (см. №7), которую пользователь и так может
не хотеть.

## UX-проблемы

### 6. Слишком длинный путь к главному действию

Нет ни `commands` (горячей клавиши), ни `contextMenus`. Сценарий сейчас: выдели → дотянись до
иконки в тулбаре (которая у большинства спрятана в меню «пазл») → дождись открытия панели →
нажми «Create Card».

**Сделано** (`f6b025d`, обновлено под панель в `69cf440`). Добавлены контекстное меню
«Create card from "…"» (только для `contexts: ["selection"]` на http/https) и горячая клавиша
`Alt+C`. Оба пути ведут в `createCardFromSelection` в `src/pages/Background/index.js`: открывается
нативная боковая панель (`chrome.sidePanel.open` — первой строкой, пока жив пользовательский жест),
текст берётся живым выделением со страницы (`info.selectionText` из меню Chrome обрезает по длине и
используется только как запасной вариант) и паркуется в storage до готовности панели.

Остаточное поведение: `handleTextSelection` выходит рано, если новый текст совпадает с текущим,
поэтому повторный `Alt+C` на том же слове ничего не сделает. Это существующая защита внутри
`CreateCard.tsx`, не трогал.

### 7. Любое выделение текста молча затирает черновик

`src/components/CreateCard.tsx:1704` вешает глобальный `mouseup` и на каждое выделение подменяет
содержимое поля. Пользователь выделил абзац, чтобы скопировать — набранный вручную текст карточки
пропал. Ни подтверждения, ни undo.

**Смягчено, но не закрыто.** После переезда на панель (`69cf440`) глобального `mouseup` внутри
React больше нет: выделение приходит из тонкого content script сообщением `SELECTION_CHANGED`, а
панель решает, принимать ли его. Но `handleTextSelection` всё ещё подставляет текст без
подтверждения, так что при открытой панели активное выделение по-прежнему может затереть черновик.
Нужно подтверждение, когда поле не пусто.

### 8. Нет онбординга

После установки — панель, которая ничего не умеет без ключа. Предупреждение
`showMissingApiKeyNotice` показывается только после неудачной попытки создать карточку.
`chrome.runtime.onInstalled` (`src/pages/Background/index.js:160`) не открывает ни welcome,
ни настройки.

**Сделано** (`19a3b58`). `onInstalled` с `reason === 'install'` открывает страницу настроек, которая
одновременно служит онбордингом. На обновлениях молчит.

### 9. Состояние видимости панели живёт в трёх местах сразу

`anki_view_prefs_v1`, `anki_ui_tab_<id>` и Redux-редьюсер `view` — синхронизировались руками
примерно в восьми местах. Для пользователя это выглядело как «панель иногда не открывается с
первого клика», «открылась не в том режиме», мигание при переключении float/dock.

**Закрыто** переездом на нативную панель (`69cf440`). Видимостью панели теперь управляет сам
Chrome, а не расширение. Редьюсеры `view` и `sidebar`, экшены и ключ `anki_view_prefs_v1` удалены —
синхронизировать больше нечего.

### 10. Привязка к `tabId` ненадёжна

Chrome переиспользует id закрытых вкладок, а старый fallback был вообще `Math.random()`. Новая
вкладка могла подхватить чужой черновик, а ключи `anki_ui_tab_*` и `anki_tab_cards*` никогда не
удалялись.

**Сделано** (`19a3b58`). `chrome.tabs.onRemoved` чистит всё, привязанное к вкладке: карточки,
UI-состояние и картинки через `dropScope`. После переезда на панель (`69cf440`) `tabId` берётся
из `chrome.tabs.query` реальной активной вкладки, а не из случайного fallback, и панель
переприцеливается на активную вкладку при переключении. Риск «чужого черновика» снят.

**Осталось:** переиспользование id вкладок Chrome'ом — свойство браузера, от которого полной
защиты нет; чистка при закрытии вкладки сокращает окно, но не устраняет его теоретически.

### 11. Картинки хранились в области видимости сайта, а не расширения

Изначально пункт был про квоту localStorage, но настоящая проблема оказалась серьёзнее и
проявлялась как баг «картинки пропадают».

Карточки пишутся в `chrome.storage.local` — хранилище расширения, общее для всех сайтов. Картинки
туда не попадали: `stripLargeImagePayload` обнуляет `image` перед сериализацией, а единственная
копия лежала в IndexedDB `vaulto-card-images`, которую открывал **content script** — то есть база
принадлежала origin посещаемого сайта, а не расширению.

Отсюда симптом: карточка, созданная на одном сайте, показывала картинку только там. На любом
другом `hydrateCardImages` искал запись в базе этого сайта, не находил и возвращал `image: null`.
Хуже того, разрешение `unlimitedStorage` на такие записи не распространяется — они жили под квотой
сайта, где браузер волен их вытеснять, а «Очистить историю» стирает подчистую. И `cardsSyncService`
отправлял на сервер `image: null`, делая потерю постоянной и распространяя её по устройствам.

**Сделано.** Добавлен `src/services/cardImageStore.ts`: каждая картинка — отдельный ключ в
`chrome.storage.local`, поэтому запись одной не переписывает остальные, а `unlimitedStorage`
наконец применяется по назначению. Индексный ключ хранит список карточек с картинками по скоупу —
он нужен, чтобы удалять осиротевшие картинки, не перебирая всё хранилище. Операции с индексом
сериализованы очередью: глобальный и вкладочный скоупы сохраняются из разных мест и могут
пересечься, а без очереди две параллельные записи затирали бы скоуп друг друга. Гидрация индекс не
использует и читает ключи прямо по id карточек, поэтому расхождение индекса не приводит к пропаже
картинок — максимум к неубранному мусору.

`src/services/legacyCardImageCleanup.ts` удаляет старые базы с сайтов. Содержимое намеренно не
спасается: картинки и так были видны только на своём origin. Быстрый путь — `indexedDB.databases()`,
который отвечает, ничего не открывая.

**Осталось:** `safeLocalStorageSetItem` (`src/store/middleware/cardsLocalStorage.ts:73`)
по-прежнему глотает `QuotaExceeded` через `return false` на пути сохранения самих карточек —
пользователь не узнает, что карточка не сохранилась.

### 12. Плавающее окно почти не ресайзится по ширине

`MAX_FLOAT_WIDTH = 360 + 48`, минимум 340 → диапазон 340–408px. Для карточки с картинкой и
примерами это тесно, а ручка ресайза обещает больше, чем даёт.

**Снято** переездом на панель (`69cf440`). Плавающего окна больше нет; ширину боковой панели
пользователь тянет сам средствами Chrome, без искусственного лимита.

### 13. Нет тёмной темы

`#ffffff` захардкожен в `src/App.tsx:180,198`, `src/components/Settings.tsx:459` и сотнях мест
инлайн-стилей. Белая панель 350px на тёмном сайте ночью — больно.

### 14. Доступность отсутствует

Инлайн-стили с `outline: 'none'` повсеместно, hover-состояния через `onMouseOver` (с клавиатуры
не работают), ни одного `aria-*`, модалки (`TextOptionsModal`, `BatchPreviewModal`,
`RecreateCardModal`) без focus-trap и без закрытия по Esc. Навигация только мышью.

### 15. Смешанные языки интерфейса

Интерфейс английский, но `src/pages/Background/index.js:104` показывает русский тултип
«Расширение недоступно на этой странице». i18n нет вообще, хотя целевая аудитория расширения для
изучения языков по определению международная.

### 16. Мелочи, которые заметны

- **KaTeX-шрифты — закрыто** переездом на панель (`69cf440`). Абсолютный путь `/assets/img/…`
  раньше резолвился в origin сайта и давал 404; из панели он указывает на origin расширения, файлы
  на месте (20 woff2 в сборке).
- **Ctrl+L — снято**: перехват жил в глобальном `keydown` внутри старого in-page React, которого на
  чужих страницах больше нет. `switchToMode` осталась пустышкой, но безвредной; заодно кандидат на
  удаление вместе с мёртвым режимом General Topic.

### 17. Стоимость переложена на пользователя без видимости расхода

`imageGenerationMode` по умолчанию `'smart'`, картинки — `gpt-image-2` 1024×1024
(`src/constants.ts`). Пользователь платит своим ключом и не видит ни счётчика расхода, ни оценки
цены карточки.

Заодно стоит проверить, что id `gpt-5.4-nano` и `gpt-image-2` реально существуют в API — при
неверном id все запросы упадут в 404, а UI покажет общую ошибку.

### 18. Поддерживаемость

Не UX напрямую, но причина, по которой UX-баги будут возвращаться:

- `src/components/CreateCard.tsx` — 7772 строки и около 60 `useState` в одном компоненте.
- Весь стайлинг инлайновый, несмотря на подключённый Tailwind.
- ~~`UniversalCardCreator.tsx` (1101 строка) не импортируется нигде~~ — удалён в `19a3b58`.
- ~~README рекламирует режим General Topic, которого больше нет~~ — README поправлен в `19a3b58`,
  там же описаны контекстное меню и `Alt+C`.
- Остаётся главное: `CreateCard.tsx` на 7772 строки и инлайновый стайлинг.

## Сделано сверх аудита: анонимный счётчик активности

Не пункт из списка проблем, а отдельная задача — понять, сколько людей пользуется расширением.
Chrome Web Store даёт только недельные цифры с задержкой, этого мало для продуктовых решений.

`src/services/usageMetrics.ts` раз в UTC-сутки отправляет `POST` на `/metrics/daily` с телом
`{ day, version }`. Дедупликация происходит на устройстве, поэтому серверу идентификатор не нужен —
он инкрементит счётчик и физически не может отличить одну установку от другой. Приватность здесь
свойство конструкции, а не обещание в политике.

Вызовы стоят в двух точках реального использования: клик по иконке и создание карточки через меню
или `Alt+C`. На `onStartup` намеренно нет — пробуждение воркера не означает, что расширением
пользовались. Нового разрешения не потребовалось.

Бэкенд — `services/cards_sync_service`, ветка `feat/anonymous-daily-active-counter`, коммит
`64a6108`: модель `daily_active`, миграция `20260722_01` и роут с атомарным upsert. День берётся
серверный в UTC, а не из тела запроса, — сбитые часы на устройстве иначе создавали бы строки за
произвольные даты. DTO запрещает лишние поля: комбинация атрибутов идентифицирует человека, даже
когда ни один по отдельности этого не делает.

**Три условия, без которых схема не работает.** Не логировать IP на этом пути во всех слоях,
включая CDN и балансировщик — они ведут свои access-логи независимо от настроек origin, и это самое
частое место, где такие схемы ломаются молча. Не ставить куки на этом пути. Не добавлять поля в
тело: это ломает исключение для агрегатного измерения аудитории, на которое схема опирается, и
тогда потребуется согласие пользователя. Флаг `vaulto_metrics_enabled` уже читается — тумблер
добавляется в UI одной строкой, когда это понадобится.
